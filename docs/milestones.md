# マイルストーン

## 全体像

| フェーズ | 目安 | 到達点 |
| --- | --- | --- |
| 企画・仮説整理 | 完了 | 誰の、どんな困りごとを解決するかと、PoCで確かめる仮説を言語化する |
| PoC準備・承認 | 次の段階 | 成功条件、撤退条件、検証相手、必要リソースを確定する |
| PoC実施 | 4週間 | 家族利用で、必須タスクの抜け・二重実施・確認負担が減るかを検証する |
| 次の判断 | PoC終了後 | 継続開発、仮説修正、または撤退・別案への切り替えを決める |

## PoCの週次マイルストーン

### 週1: 基準値と非実装検証を取る

- 家族が使うスマホ・ブラウザなど、技術前提を確認する
- 必須タスクの抜け、二重実施、確認の電話・LINEの回数を計測する
- 家族LINEなどを使った人力運用（Wizard of Oz）を始める
- P1ロールプレイを実施し、課題の深刻さと運用上のつまずきを確認する

**完了条件:** 検証前の基準値と、実際の利用者から得た初期フィードバックが記録されている。

### 週2: 技術と需要を確かめる

- Webアプリで、複数端末のタスク状態同期を試す
- 必要に応じてブラウザ通知またはLINEなどによる通知方法を検証する
- ティザーを使い、実在の相手10人にヒアリングする
- 買い切り価格への支払意思と、既存手段との違いの理解度を確認する

**完了条件:** 技術的に最小構成が成立する見込みと、需要検証の結果が整理されている。

### 週3: 最小アプリを配布する

- タスク3件程度の最小アプリを実装する
- 「やったよ」ボタン、未完了表示、実施者・時刻の記録を入れる
- URLまたは招待リンクで家族に共有する
- 日常運用を開始し、利用上の問題を記録する

**完了条件:** 家族が実際の生活の中で使える状態になり、運用データを取り始めている。

### 週4: 効果を計測して判定する

- タップ率、抜け・二重実施の件数、確認回数を計測する
- 成功条件と失敗・撤退条件に照らして結果を判定する
- 技術面、利用面、支払意思の学びをまとめる
- 継続開発、仮説修正、または別案への切り替えを決める

**完了条件:** 数値に基づくPoC結果と、次の意思決定が文書化されている。

## PoC後の判断

- **継続:** 家族利用の継続率と課題改善が成功条件を満たし、技術前提も成立する
- **修正:** 一部の仮説だけが外れた場合に、入力方法、通知、対象タスクなどを見直して再検証する
- **撤退・転換:** 利用継続、効果、技術成立性のいずれかが大きく不足する場合は、入力ゼロ案や店舗向けの検証へ切り替える
