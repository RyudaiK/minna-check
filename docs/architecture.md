# 最低限のアーキテクチャ

## 目的

家族がスマホのブラウザから同じ必須タスク一覧を見て、誰かが「やったよ」を押した結果を、他の家族の画面にも反映する。PoCでは、家族4人程度・1日数件のタスクを無理なく扱える最小構成にする。

## 採用構成

```text
[スマホブラウザ]
       |
       | HTTPS
       v
[Vercel]
 Next.js（画面・Server Actions/API）
       |
       | Supabase Client / HTTPS
       v
[Supabase]
 Auth（ログイン）
 PostgreSQL（タスク・実施記録）
 Realtime（状態変更の購読）
```

| 層 | 採用技術 | 役割 |
| --- | --- | --- |
| 画面 | Next.js | タスク一覧、完了操作、家族招待画面を提供する |
| 認証 | Supabase Auth | 家族メンバーを識別し、他家族のデータを見せない |
| データ | Supabase PostgreSQL | 家族、メンバー、タスク、実施記録を保存する |
| リアルタイム | Supabase Realtime | タスク完了時に同じ家族の画面を更新する |
| ホスティング | Vercel | WebアプリをHTTPSで公開する |
| 開発 | TypeScript | 画面とデータの型を揃える |

## 最小データモデル

### households

- `id`: 家族ID
- `name`: 家族名
- `created_at`: 作成日時

### household_members

- `household_id`: 家族ID
- `user_id`: Supabase AuthのユーザーID
- `display_name`: 画面に表示する名前
- `created_at`: 参加日時

### tasks

- `id`: タスクID
- `household_id`: 家族ID
- `title`: タスク名
- `task_date`: 対象日
- `is_completed`: 完了状態
- `completed_by`: 完了したメンバーのユーザーID（未完了なら空）
- `completed_at`: 完了日時（未完了なら空）

PoCでは、タスクを1日1回のレコードとして作成する。完了後の取り消しや履歴が必要になった時点で、`task_completions` のような履歴テーブルへ分離する。

## 主要な処理

### 1. 初回参加

1. ユーザーが招待リンクを開く
2. Supabase Authでログインする
3. 招待情報を確認し、`household_members` に参加登録する
4. 当日の `tasks` を取得して一覧表示する

### 2. タスク完了

1. ブラウザで「やったよ」を押す
2. サーバー側で、ログインユーザーがその家族のメンバーか確認する
3. 未完了のタスクだけを条件に更新する
4. `completed_by` と `completed_at` を同時に保存する
5. Supabase Realtimeで同じ家族の画面を更新する

完了更新は「`is_completed = false` のときだけ成功」という条件付き更新にする。これにより、2人がほぼ同時に押しても二重実施として記録しにくくする。

### 3. 当日の一覧表示

- `household_id` と `task_date` で当日のタスクを取得する
- 未完了タスクを上に表示する
- 完了済みの場合は、実施者名と実施時刻を表示する
- 画面表示の進捗は「完了数 / 全タスク数」で計算する

## 認可とデータ保護

- SupabaseのRow Level Security（RLS）を有効にする
- `household_members` に所属しているユーザーだけが、その家族の `tasks` を読める・更新できる
- クライアントにSupabaseの秘密鍵を置かない。ブラウザには公開キーだけを渡す
- タスク完了時の家族IDやユーザーIDは、画面から受け取った値をそのまま信用せず、ログイン情報とDB上の所属から判定する
- 招待リンクには推測しにくいトークンを使い、使用後または期限到達後に無効化する

## 通知の扱い

PoCの最初の必須条件は、Realtimeによる画面更新とする。ブラウザ通知は次の段階で追加する。

- ブラウザ通知の許可をユーザーから取得する
- 未完了タスクの締切前通知は、定期実行処理で判定する
- 通知がブラウザや端末の制限で安定しない場合は、まずアプリ内の未完了表示を正とする
- LINE通知やネイティブプッシュ通知は今回の最小構成に含めない

## デプロイと環境変数

- GitリポジトリからVercelへデプロイする
- SupabaseのURLと公開キーはVercelの環境変数で管理する
- ローカル開発用と本番用のSupabaseプロジェクトを分けるか、少なくとも本番データをローカル開発から直接変更しない
- 本番公開前に、スマホ幅のブラウザでログイン、招待、完了操作、複数端末更新を確認する

## PoCで作らないもの

- iOS/Androidのネイティブアプリ
- 家族内チャット、コメント、汎用カレンダー
- 詳細な担当割り当て、繰り返し予定、課金処理
- センサーによる自動検知
- 管理画面や複雑な権限階層

## 最初の技術検証

1. Supabase Authで2つのユーザーを作成する
2. 同じ家族に所属させ、当日のタスクを1件作成する
3. 片方のブラウザで「やったよ」を押す
4. もう片方のブラウザに完了状態、実施者、時刻が反映されることを確認する
5. 別の家族のユーザーからタスクが見えないことを確認する

この検証が通れば、週3の家族向け最小アプリ実装へ進む。
